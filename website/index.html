A porn blocker that does not ask for your trust.

Quiet filters adult domains on the device. On Android it sits in front of every app's DNS lookups; in a browser it checks every request the browser makes. Your lists stay on your device, there is no account, no server and no telemetry, and nothing is uploaded anywhere.

On the phone: every app, not just a browser

Android has exactly one mechanism a normal app can use to see what other apps are doing on the network: a VpnService. Quiet uses it in the narrowest way it can - only DNS is routed into the tunnel, so there is no user-space TCP/IP stack, no throughput cost and negligible battery drain.

Quiet for Android

This platform

Blocks adult domains for every app on the phone, from a list that is already inside the APK. Works offline, does not care which app is asking, and restarts itself after a reboot.

Download the APK

Signed with Android's debug key unless the repository has signing secrets. Fine for testing, and it means a later, properly signed build cannot update over it.

What it does on Android

  • A PIN is mandatory before the tunnel will start, and asked for before anything that weakens protection.
  • Commitment lock: protection refuses to switch off until a timer runs out.
  • Family resolver presets, so upstream filtering backs up the lists.
  • Encrypted-DNS bypass is blocked, with a list of ~65 DoH/DoT endpoints in the package.
  • Choose how blocked names answer: empty answer, 0.0.0.0 or NXDOMAIN.
  • Optionally hide the launcher icon, and lock uninstalling through Android's device-owner mode.

Installing it

  1. Download the APK from the release and open it. Android will ask whether to allow installing from your browser or files app.
  2. Set a 4-8 digit PIN. There is no way past this screen: native code refuses to create the tunnel without one.
  3. Grant the VPN permission Android offers you. The bundled adult list is already installed, and filtering starts immediately.
  4. Nothing else changes: afterwards it behaves like any other app, and it is called Quiet in the launcher, in notifications and under Settings → Apps.

In a browser: the same lists, for the browser you already use

One source tree builds a package per browser. The lists are baked into the package as declarative rules, so the extension makes no network requests at runtime - it hands the rules to the browser, and the browser does the matching.

Chrome, Edge, Brave, Opera, Vivaldi

Your browser
  1. Download the zip and unzip it somewhere permanent.
  2. Open chrome://extensions and turn on Developer mode.
  3. Load unpacked → pick the unzipped folder.
  4. Open the extension's settings and set a PIN.

Firefox

Your browser
  1. Download the .xpi.
  2. Open about:debugging#/runtime/this-firefox.
  3. Load Temporary Add-on → pick the file.
  4. Set a PIN in the extension's settings.

Firefox treats an unsigned add-on as temporary: it is forgotten when Firefox restarts. A build signed through addons.mozilla.org would install for good.

What neither of them can do

A blocker that overpromises is worse than no blocker, so this is the list the READMEs carry too.

On Android

  • Blocking is by domain name. A site reached by IP address, or served from a domain no list knows yet, gets through; the upstream family resolver is the second line of defence.
  • No password on the uninstall button. That dialog belongs to Android. Real uninstall protection needs device-owner mode, granted once over USB.
  • Custom encrypted DNS bypasses filtering, so leave Private DNS on Off/Automatic and turn off "Use secure DNS" in your browser.
  • Never enable "Block connections without VPN". Quiet is a DNS filter, not a full tunnel, and lockdown mode would take you offline.
  • Hiding the icon is not uninstall protection. It stops reminding you, and it is reversible from Settings.
  • It is not parental-control software. Per-app rules, profiles and remote management are out of scope.

In a browser

  • It covers this browser in this profile only. Other browsers, other apps and the rest of the machine are out of its reach.
  • There is no family resolver behind it. A browser cannot change your DNS, so the lists are the only line of defence.
  • Counts are page loads, not every blocked sub-resource. Browsers only report the load, and the permission that would expose individual matches is limited to development builds - so Firefox counts are a best effort, and the UI says so.
  • An extension cannot stop you switching it off. The PIN is a speed bump for the moment you want to stop, not a lock on the browser.
  • Optional OISD lists are a build-time choice, because nothing is downloaded at runtime; when a list is missing from the build, the UI says so.

What happens to your data

Leaves the device

  • The DNS queries themselves, relayed to the resolver you pick.
  • Blocklist downloads, and only for list URLs you added yourself.

The browser extension adds nothing: it makes no network calls at runtime at all.

Stored on the device

  • Your settings, the list files and your allowlist.
  • A rolling seven-day log of blocked domain names, and daily counters.
  • A salted hash of your PIN. The PIN itself is never stored.

Never collected

  • Which app made a request, or any page content.
  • Identifiers, crash reports, analytics, accounts.
  • Anything by this page: it sets no cookies and loads nothing from third parties.

Built and verified in the open

Build it yourself

git clone https://github.com/kennethyork/Quiet.git
cd Quiet && npm install

# Android (needs Node 20+, JDK 17+, Android SDK)
npx expo run:android

# Browsers (needs nothing but Node)
cd browser-extension
npm test && npm run build

The matcher exists twice on purpose: in Kotlin for the tunnel and in JavaScript for the extension, with the same test cases run against both, so the two cannot disagree about what is blocked.
